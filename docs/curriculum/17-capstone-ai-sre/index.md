# Phase 17 — AI-SRE Capstone

> Combine everything into a platform that investigates incidents, proposes and executes approved remediation, verifies recovery and writes the report.

**Status:** 📋 planned · **Estimated effort:** 3–4 weeks · **Prerequisites:** Phases 00–16 and Projects 1–7.

## Overview

The AI-SRE Platform is the final project and the whole course in one system.

```text
                         USER
                           │
                      API Gateway
                           │
                      AI SRE API
             ┌─────────────┼─────────────┐
        Kubernetes     Prometheus       Loki
             └─────────────┼─────────────┘
                       AI Agent
             ┌─────────────┼─────────────┐
            RAG        LLM Gateway      Tools
             │             │             │
         Vector DB      LLM Server    DevOps APIs
                           │
                          GPU
                           │
                      Kubernetes
```

The system must:

1. Receive an incident question.
2. Inspect infrastructure.
3. Query metrics.
4. Inspect logs.
5. Inspect deployment history.
6. Search runbooks.
7. Generate a root-cause hypothesis.
8. Provide evidence.
9. Recommend remediation.
10. Request approval.
11. Execute approved remediation.
12. Verify recovery.
13. Produce an incident report.

## Why a DevOps engineer needs this

This is the portfolio piece that shows you can design, build, secure, observe, scale and operate an AI system end to end, and explain every decision. It is also the first time destructive actions are allowed, and only behind explicit approval, least privilege, a sandbox, audit logs and rollback.

## Learning objectives

- Design the architecture, SLOs and trust boundaries for an AI-SRE platform.
- Integrate the LLM gateway, RAG, agent, observability and GPU serving from earlier projects.
- Implement approval-gated remediation with audit and rollback.
- Run a game day: inject failures, let the platform investigate, verify its diagnosis and remediation.
- Write an incident report generated by the platform and a post-mortem written by you.
- Present the system and defend its decisions.

## Assessment

- **Knowledge check:** a cumulative 15-question check across the course.
- **Practical:** the platform diagnoses an unseen injected failure correctly with evidence.
- **Troubleshooting:** the platform proposes a wrong remediation; trace why and fix the guardrail.
- **Architecture:** present the system to a panel and answer "what happens at 10× traffic?" and "what happens when the GPU node dies?"
- **Interview:** design an AI platform for production.

## Checkpoint

You have completed the course when the platform runs, the game day passes, every document exists, and you can walk into a room and hear "we need to put this AI workload into production" and answer:

> "Let's design the architecture, define the SLOs, choose the compute, package the workload, deploy it, secure it, instrument it, establish autoscaling, control the cost, test failure modes, and build the operational runbooks."
